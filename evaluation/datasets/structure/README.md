# Structural retrieval benchmark

A third, separate evaluation dataset (`structural-retrieval`, **v1.0.0**, 41 cases: 31 answerable, 10 unanswerable), added on 2026-10-16 to test whether retrieval works across document **structures** and **question formulations**, not just for one PDF. Same schema, evaluator, report format, CLI, and MLflow experiment as the core (`../dataset.json`) and VEIL (`../veil/`) datasets, which stay unchanged.

```bash
cd backend
.venv/bin/python -m app.evaluation.run_evaluation --dataset ../evaluation/datasets/structure/dataset.json --validate-only
.venv/bin/python -m app.evaluation.run_evaluation --dataset ../evaluation/datasets/structure/dataset.json --label structural   # ~2.5 min with judge
.venv/bin/pytest tests/test_structure.py   # deterministic extraction/chunking/retrieval checks on the same fixtures (no LLM)
```

## Corpus and provenance

| File | Origin | Structure exercised |
| --- | --- | --- |
| `northwind_service_tiers.pdf` | Synthetic, generated by `build_pdf_fixtures.py` (fictional SaaS) | Slide-style page: title, three stat cards, prose section with headings, a tier → limitations table whose cells are separate text boxes with wrapped lines, a bullet list. The prose and the table both mention request limits with different numbers. |
| `incident_severity_matrix.pdf` | Synthetic, `build_pdf_fixtures.py` (fictional operations team) | Two A4 pages: a four-column severity table written **row-major** (line by line across columns) with wrapped cells; page 2 prose mentions SEV-2 with a different number. |
| `kestrel_ridge_staff_handbook.txt` | Synthetic (fictional observatory) | Headings, nested bullet lists, explanatory paragraphs. |
| `millbrook_reservoir_inspection_report.txt` | Synthetic (fictional reservoir) | One ~350-token paragraph that crosses chunk boundaries. |
| `harlow_parking_permits_north_campus.txt`, `harlow_parking_permits_south_campus.txt` | Synthetic (fictional institute) | Two documents with identical headings and wording but different facts. |
| `SIH2026_BinaryBrainCells_PS_26171.pdf` | Byte-for-byte copy of the VEIL proposal (SHA-256 `26ebc25c…`, see `../veil/README.md`) | The page-4 risk table from the owner's manual tests. |

`build_pdf_fixtures.py` writes the two synthetic PDFs deterministically (byte-identical on every run; checked by `tests/test_structure.py`). It positions Helvetica text the way slide and report generators do; no third-party content.

## Cases

| IDs | What they test |
| --- | --- |
| STR-VEL-001…006 | The owner's Queries A (generic "What mitigates free-tier rate limits?"), B (table-referenced), C (all four risk → mitigation rows, eight facts); a wrapped row in both directions; a proposed mitigation vs. an implemented capability (face detection) |
| STR-TAB-001…007 | Table lookup with the table's own terms, paraphrase without the heading, relationship between two fields of a row, all rows, prose vs. table with shared keywords, reverse lookup, a fact in a stat card |
| STR-INC-001…006 | Row-major table: direct lookup, low-overlap paraphrase, reverse lookup, all rows, prose page vs. table, partial evidence (the ticketing tool is not named and must not be invented) |
| STR-HDG-001…005 | Nested bullets under headings, all entries across groups, low-overlap paraphrase (thunderstorm vs. lightning), a fact inside a paragraph |
| STR-LNG-001…004 | Facts at different positions of a long paragraph |
| STR-SIM-001…003 | Choosing between near-identical documents; combining both |
| STR-VEL-007/008, STR-NEG-001…008 | Negative controls: absent details, lookalike entities (a "Business" tier, SEV-5, weir D, an East Campus), unrelated questions |

Questions and expected answers were written before any run of the changed pipeline and were not edited afterwards. One required fact (`STR-TAB-001`) also lists the glued spelling `1,000requests` produced by the old extractor, only so the dataset validates under both extractors.

## Known lexical limitations (recorded after the runs, not corrected, to keep before/after comparable)

- `STR-VEL-005`'s forbidden pattern does not handle negation: an answer saying the proposal "does not state that VEIL currently detects faces" is flagged as unsupported content.
- Required facts are matched lexically (`2 working days` vs. "two business days" would be missed).
