# RAGGuard — Decision Record

Authoritative record of project decisions. Sections:

1. **Confirmed decisions** (`D-xxx`) — binding. Change only via section 4.
2. **Planned defaults** (`P-xxx`) — the intended approach; may be adjusted in the implementing stage, with the change recorded here.
3. **Unresolved decisions** (`U-xxx`) — deliberately open; resolved in the stated stage and then moved to section 1 or 2.
4. **Changes to previous decisions** — what changed, when, and why.

Do not introduce alternative frameworks, databases, or services without recording the reason here.

---

## 1. Confirmed decisions

| ID | Date | Decision | Rationale |
| --- | --- | --- | --- |
| D-001 | 2026-10-12 | Product name is **RAGGuard**. | Communicates a RAG system protected by quality gates. |
| D-002 | 2026-10-12 | Supported input formats are **PDF and TXT**. | Covers the core use case while keeping ingestion scope bounded. |
| D-003 | 2026-10-12 | Vector store is **Qdrant**. | Purpose-built vector database with payload metadata (needed for document/page citations), filtering, and a simple container deployment. |
| D-004 | 2026-10-12 | Frontend stack: **React, TypeScript, Vite, Tailwind CSS, Lucide icons**, and **Three.js with React Three Fiber** for a small number of purposeful 3D visualizations. | Typed, fast-to-build SPA; Tailwind supports a token-based design system; Lucide gives one consistent icon set; R3F keeps 3D code declarative and isolated. |
| D-005 | 2026-10-12 | Backend stack: **Python, FastAPI, Pydantic**. | Python fits the RAG/evaluation ecosystem; FastAPI + Pydantic give typed request/response contracts. |
| D-006 | 2026-10-12 | Evaluation and tracking: **Python evaluation scripts, pytest, httpx, MLflow**, and a **fixed, version-controlled evaluation dataset**. | Reproducible, comparable measurements tied to code and dataset versions. |
| D-007 | 2026-10-12 | DevOps: **Docker, Docker Compose, GitHub Actions, Git**. | Reproducible local environment and an automated, auditable release gate. |
| D-008 | 2026-10-12 | **Live query handling and offline/CI evaluation are separate flows** sharing one pipeline implementation. Evaluation runs on proposed code changes (and on demand), never per user query. | Keeps user latency and cost unaffected by evaluation, while ensuring evaluation measures the real pipeline. |
| D-009 | 2026-10-12 | A **failed quality gate prevents image build and release** jobs. A blocked release does **not** take down the currently deployed version. | The gate protects users from regressions without causing outages. |
| D-010 | 2026-10-12 | Answers must include **source references** (document, and page where available). When evidence is insufficient the system returns a **safe fallback** rather than an unsupported answer. | Traceability and honesty are the product's core value. |
| D-011 | 2026-10-12 | The **LLM judge is a supplementary evaluator**, used alongside deterministic checks, never as sole ground truth. | LLM judges are noisy and biased; gating on them alone would be unreliable. |
| D-012 | 2026-10-12 | **Quality thresholds are defined only after a measured baseline**, and are stored in version control. | Thresholds chosen before measurement would be arbitrary. |
| D-013 | 2026-10-12 | **UI principle:** the interface must look like a deliberately designed product — precise, evidence-focused, restrained — not a generic AI dashboard. Governed by `docs/UI_DESIGN_SPEC.md`. | Visual credibility matters for a tool whose purpose is trust and traceability. |
| D-014 | 2026-10-12 | **3D is limited** to the pipeline visualization (document → chunks → vectors → evidence → answer), lazy-loaded, with reduced-motion support and a non-3D fallback. | 3D should explain the product, not decorate it or hurt performance. |
| D-015 | 2026-10-12 | **No fabricated data in the working application.** Sample data must be visibly labelled as demonstration data. | A QA tool showing invented metrics would undermine its own purpose. |
| D-016 | 2026-10-12 | Repository is a **single repository** with `frontend/`, `backend/`, `evaluation/`, `deployment/`, `docs/`, `.github/` (structure created in Stage 1). | Keeps code, dataset, CI, and documentation versioned together. |
| D-017 | 2026-10-12 | **Kubernetes, canary deployment, and advanced monitoring are optional extensions**, not initial requirements. | Keeps the core deliverable focused. |
| D-018 | 2026-10-12 | Documentation roles: `PROJECT_CONTEXT.md` = current state, `ROADMAP.md` = stage status, `DECISIONS.md` = decisions, `PROGRESS_LOG.md` = append-only history. | One source of truth per kind of information. |
| D-019 | 2026-10-12 | **Default generation provider: Ollama** (local HTTP API, non-streaming `/api/chat`, `think: false`) with model **`qwen3.5:9b`**. Selected by `GENERATION_PROVIDER=ollama` (default). Resolves U-001. | Free, private, local inference with no API key; the model was already installed. `think: false` returns only the final answer (no reasoning trace); a defensive filter also strips `<think>` blocks. |
| D-020 | 2026-10-12 | **Gemini is optional** (`GENERATION_PROVIDER=gemini`, official `google-genai` SDK, `GEMINI_API_KEY`, `GEMINI_MODEL`). Never the default, never called by the automated test suite, never probed by `/health`. **No automatic failover** between providers: a failing provider returns an error. | Keeps normal development and CI free of credentials and cost; silent failover would hide outages and change which model produced an answer. |
| D-021 | 2026-10-12 | **Embeddings: `sentence-transformers/all-MiniLM-L6-v2`**, run locally, **384 dimensions**, L2-normalized; the same model embeds chunks and queries. Qdrant collection uses **COSINE** distance, so scores are cosine similarities in [-1, 1]. Resolves U-002. | Small (~90 MB), fast on CPU/MPS, no API key. Collection dimension/distance are checked against the model on first use; a mismatch is a clear configuration error. |
| D-022 | 2026-10-12 | **PDF extraction: `pypdf`**, page by page with 1-based page numbers. Pages without extractable text are skipped; a PDF with no extractable text (scanned/image-only) is **rejected as unsupported** (no OCR). Password-protected PDFs are rejected. TXT must be UTF-8. Resolves U-003. | Pure-Python, no system dependencies, and gives page-level text for citations. OCR is out of scope (see `PROJECT_CONTEXT.md`). |
| D-023 | 2026-10-12 | **Chunking: 180 tokens with 30-token overlap**, measured with the embedding model's own tokenizer; chunks never cross a PDF page boundary; each chunk stores document ID, filename, file type, page number (null for TXT), chunk index, text, character span, and token count. **Default top-k = 4** (request override 1–20). Values are provisional and tuned in Stage 4. Resolves U-004. | 180 tokens fits MiniLM's 254-content-token limit (256 minus 2 special tokens) with margin, so no chunk is truncated at embedding time. Page-bounded chunks make page citations exact. |
| D-024 | 2026-10-12 | **Evidence rule / fallback policy:** chunks with cosine score `>= MIN_RETRIEVAL_SCORE` (provisional **0.35**) are the evidence. If none remain (or nothing is retrieved), the safe fallback is returned **without calling the LLM**. If evidence passes, the prompt lets the model reply `INSUFFICIENT_EVIDENCE`, which is also mapped to the fallback (`fallback_reason: model_declined`). Fallback responses carry no sources. Resolves U-005. | Two layers: similarity filters clearly unrelated questions cheaply; the model catches related-but-unanswered questions that similarity cannot (observed: an unanswerable question scored 0.68). Neither guarantees correctness; Stage 4 measures and tunes this. |
| D-025 | 2026-10-12 | **Uploads:** one file per request, `.pdf`/`.txt` only, **10 MB** default limit (`MAX_UPLOAD_SIZE_MB`), content signature checked. **Original files are not retained**; only chunk text and metadata are stored in Qdrant. Every upload gets a new UUID document ID. Resolves U-006. | Minimal storage and attack surface; chunk text is sufficient for citations and excerpts. |
| D-026 | 2026-10-12 | **Backend toolchain:** Python **3.13** (Homebrew; 3.12 not installed on the development machine), project-local virtualenv at `backend/.venv`, `pip` with exact pins in `backend/requirements.txt` (+ `requirements-dev.txt` for pytest, ruff, mypy). Tool config in `backend/pyproject.toml`. Resolves the backend part of U-007. | Uses the available interpreter without installing another runtime; exact pins make the verified environment reproducible. |
| D-027 | 2026-10-12 | **Qdrant client mode:** embedded **local persistent mode** at `QDRANT_LOCAL_PATH` (default `qdrant_storage/`, git-ignored) when `QDRANT_URL` is empty; **remote server** when `QDRANT_URL` is set. One client instance never mixes modes. Collection name from `QDRANT_COLLECTION_NAME`. | No separate service needed for development; the same code works against a server (expected for Docker Compose in Stage 6). Local mode allows only one process per storage folder. |
| D-028 | 2026-10-12 | **Shared pipeline module:** `backend/app/pipeline.py` (`RAGPipeline`) orchestrates ingestion and question answering; API routes are thin wrappers. The Stage 4 evaluation runner must call this same class. | Implements D-008 (one pipeline for live and evaluation paths) and keeps orchestration out of route handlers. |
| D-029 | 2026-10-12 | **Stage 2 API:** `POST /ingest`, `POST /query`, `GET /health`, plus `GET /documents` and `DELETE /documents/{document_id}`. Errors use `{"error": {"code", "message"}}` with appropriate HTTP status. `/health` always returns 200 while the API is up and reports per-component readiness (`status: ok/degraded`, `generation_ready`). | Listing and deletion were required by the Stage 2 tasks and completion criteria in `ROADMAP.md` ("listed with status"); see section 4. |
| D-030 | 2026-10-13 | **Frontend toolchain:** Node 24.21, npm 11.19 with `frontend/package-lock.json` retained; React 19.3, TypeScript 6.0 (`strict`, `noUncheckedIndexedAccess`), Vite 8, Tailwind CSS 4.3 (CSS-first `@theme` bound to the design tokens; default palette, font sizes, radii, and shadows removed), Lucide React, three 0.186 + React Three Fiber 9.8, Vitest 5 + React Testing Library + jsdom, ESLint 10 + typescript-eslint + react-hooks 7. Resolves the frontend part of U-007. | Matches the Stage 1 stack (D-004) at current versions. Removing Tailwind's defaults makes ad-hoc colours and sizes impossible, which enforces UI spec §15.1. |
| D-031 | 2026-10-13 | **No router library.** Four top-level views use minimal hash routing (`#/workspace`, `#/evaluation`, `#/experiments`, `#/pipeline`) in `src/app/useRoute.ts`. Settles P-008. | Only one view has real functionality; a dependency is not justified yet. Revisit if views need nested routes. |
| D-032 | 2026-10-13 | **3D implementation:** three.js + React Three Fiber only (no `@react-three/drei`), procedural geometry, `frameloop="demand"`, DPR capped at 1.5, no animation loop. The 3D module is a separate lazily loaded chunk. **Bundle budgets:** main JS ≤ 100 kB gzip (measured 91 kB), 3D chunk ≤ 260 kB gzip (measured 242 kB; three.js cannot be tree-shaken under R3F). | Keeps the initial view independent of WebGL and the 3D chunk; avoids a helper library (UI spec §10.4). |
| D-033 | 2026-10-13 | **Fonts self-hosted** through `@fontsource` packages bundled by Vite: IBM Plex Sans 400/500/600, IBM Plex Mono 400/500, Source Serif 4 400/600, Latin subsets, `font-display: swap`. Implements P-007. | No runtime font CDN dependency. |
| D-034 | 2026-10-13 | **Palette finalized** (P-006): spec values kept except `ink-500` `#676A71`→`#5F6269` and `status-warn` `#A85A16`→`#965012` (both failed 4.5:1 on `paper-200`); added `line-strong` (control borders, ≥ 3:1 on every surface) and `on-accent` (text on accent fills); dark theme values defined in `src/styles/tokens.css`. Focus ring = accent outline plus ink inner edge. Verified by `src/test/units.test.ts` (WCAG ratios, both themes) and Lighthouse accessibility 100 in both themes. | Contrast requirements of UI spec §12 are met and enforced by a test. |
| D-035 | 2026-10-13 | **Frontend API integration:** one typed client (`src/lib/api/client.ts`) with per-endpoint functions (`endpoints.ts`), runtime response validation (`guards.ts`), timeouts (query 200 s, ingest 300 s, list/delete 15 s, health 8 s), and normalised errors (`network`, `timeout`, `http` with backend code/message, `malformed`, `aborted`). Base URL from `VITE_API_BASE_URL` (default `http://localhost:8000`). Never substitutes data when the API fails. Types in `src/types/api.ts` mirror the Pydantic schemas exactly. | Keeps API logic out of components and makes failure states explicit. |
| D-036 | 2026-10-13 | **Evidence Trace data model:** four stations — Documents → Chunks → Evidence → Answer — built only from the `/query` response and `GET /documents`. Positions encode page number, chunk order (`chunk_index`), response rank, and `cited`; link strength from chunk to evidence is the real cosine score; only cited sources link to the answer. Large documents are drawn scaled (reported in the UI). The spec's "Vectors" station is omitted because the API exposes no embedding coordinates. 2D SVG fallback when: no WebGL, reduced motion, viewport < 768 px, user preference (remembered in `localStorage`), while the 3D chunk loads, or if it fails. | Honours "do not fabricate embedding coordinates, relevance values, or retrieval paths". |
| D-037 | 2026-10-13 | **Citations:** an `[Sn]` token in the answer text becomes an interactive marker only when `Sn` exists in that response's `sources`; the frontend never creates citations. The API returns whole chunk excerpts, so the selected passage is marked (accent rule) instead of a sub-span highlight. | The backend owns source references (D-010); span-level data does not exist. |
| D-038 | 2026-10-13 | **Workspace behaviour:** conversation is in-memory for the browser session only (no persistence, no accounts). Uploads are one file at a time via `fetch` with an indeterminate "Indexing" state and elapsed time, because the API reports no step progress. Questions can be limited to ticked documents (`document_ids`). Layout: ≥ 1280 px three columns; 1024–1279 px evidence as a side sheet; < 1024 px one column with a Documents · Ask · Evidence switcher. | Stage 3 scope; avoids simulated progress; simpler than the spec's `md` sheets while meeting the responsive criteria. |

## 2. Planned defaults

| P-009 | Stage 4 direction (stated by the project owner, 2026-10-13) | Stage 4 covers: an automated evaluation dataset; deterministic retrieval and fallback metrics; a **local** LLM-as-judge (supplementary, D-011); threshold analysis from a measured baseline (D-012); and reproducible **JSON and Markdown** reports (written under `evaluation/results/`, P-005). The judge model, prompt, and weighting remain open (U-009); the Stage 4 roadmap tasks (API exposure of results, Evaluation view) are unchanged. | Stage 4 |
